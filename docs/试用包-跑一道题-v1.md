# 试用包：跑一道题，把过程发回来（v1）

> 给试用同学看的一页说明。全程在你自己的电脑上，**不联网、不装 App、不用注册**。
> 一次大约 10–15 分钟。

## 你要做的一件事

有一道小题：**核对一份订单数据，写出一份 `report.json`**。
题目里的数据不在文件里，而在一个**本机的小服务**上——你要通过它提供的两个工具把数据取出来、
算对、写回去。怎么取、取几次、参数给多少，由你决定，这就是我们要看的东西。

## 准备（一次就够）

1. Python 3.10 或更新（`python --version` 看一眼）。
2. 装两个依赖：`pip install pyyaml jsonschema`（用 zip 包的话，`start.bat` 会自动装）
3. 拿到这个项目目录（`.zip` 解压，或 `git clone`）。

## 三条命令

```bash
# ① 起点：起服务（会打印题面、可用工具、一段可直接跑的示例）
python scripts/lab.py --task dbg-001-order-report --log calls.jsonl

# ② 另开一个窗口，让 Agent 去调
#    屏幕上会显示类似 服务地址 http://127.0.0.1:8765
#    把「题面 + 工具清单 + 这个地址」整段贴给你的 Agent（Claude Code / Cursor / 自己写的脚本都行），
#    或者直接改屏幕上那段示例代码。

# ③ 做完回到 ① 的窗口按 Ctrl+C
```

**不要手写过程记录。** 服务在 ① 里已经把你每一次工具调用记进 `calls.jsonl` 了——
包括参数给错、服务报错、你再重试的那些次。**这些"走错"的调用正是我们要看的**，别删、别改。

## 没有 Agent 也能试

不是所有人手上都有 Claude Code / Cursor。**没有也能试**，包里带了一个演示脚本，
它替你发请求、替你写报告，你只负责看报告：

```bash
python try.py http://127.0.0.1:8765             # 只拉到一半、报错不重试（初学者常见写法）
python try.py http://127.0.0.1:8765 --mode ok   # 拉全、重试、剔掉无效行
```

两次跑完对着看：同一道题，第一份报告会指出"结论不对"和"失败了没重试"，第二份全绿。

> **两件事要分清**：
> - `try.py` 是**说明书**，不是练习。它跑出来的报告是**脚本犯的错**，不是你犯的错——
>   它能让你 30 秒看清"报告长什么样子、会说哪些话"，但**验不了你能不能学会**。
> - 想真的做一遍：把题面和那个地址贴给豆包 / DeepSeek，让它写一段 Python 按题面调这两个工具。
>   那份提交才是"你的"，错了也是你真会踩的坑。

## 发回来

- `calls.jsonl`（②③ 步骤自动生成的，在项目根目录）
- 一句话说明：你是用什么跑的（Claude Code / Cursor / 自己写的脚本 / 手工 curl）

## 再回我三句话（比"你觉得好用吗"有用得多）

1. 用你自己的话说：报告指出你哪一步错了，证据是什么？
2. 报告里哪一句话你看不懂、最卡在哪？
3. 做完这道题，你下一步想做什么？

> 自评"我看懂了"参考价值很低；**复述**一遍才看得出是不是真懂。
> 答不上第 3 句也照实说——那正好说明报告和"接下来练什么"之间断了。

## 已知边界（先说清，免得你以为是 bug）

- 服务只在本机 `127.0.0.1`，**故意不上网**；手机连不上是正常的，这轮不用手机。
- 它**不判对错**，只按声明回放数据。你本地调通不等于能得分——判分在提交之后。
- 只认这道题声明的两个工具（`fetch_orders` / `write_report`）；你用别的办法取数，
  过程里就没有那次调用，判分侧看不见。
- 这套东西目前在试用阶段，**不是多用户平台**，你交上来的日志只在这台机器上用。

## 维护者侧：收到 `calls.jsonl` 之后（三步，不用手工整理）

```bash
# ① 日志 → 提交 JSON（task_version 从任务 YAML 取，不让提交方自己写）
python scripts/lab.py --from-log calls.jsonl --task dbg-001-order-report \
    --user u-trial-01 --out submission.json

# ② 起提交接口（默认只绑 127.0.0.1，无鉴权，别放到公网）
python src/arena/submission_api.py --db trial.db --port 8080

# ③ 交上去拿报告
curl -X POST http://127.0.0.1:8080/submissions -H "Content-Type: application/json" \
     -d @submission.json
```

报告还有两个出口，按场景挑：

```bash
# ④-a 直接让服务渲染（报告已经落库，浏览器打开就是那一页）
#      http://127.0.0.1:8080/submissions/<submission_id>/report.html

# ④-b 离线存成文件发出去（自包含，手机也能开）
python -m arena.report_html --report report.json --out report.html --task dbg-001-order-report
#      Windows 上把 PYTHONPATH=src 带上：set PYTHONPATH=src && python -m arena.report_html ...
```

报告里能直接看出：几次调用、哪条检查没过、归到哪种错法、缺哪个技能。
`docs/error-patterns-v0.yaml` 的 `plain` 字段就是给人看的那句大白话。
导出的 HTML 里**没有断言 id、没有字段名**（`tests/test_report_html.py` 锁着这条）——
给同学看的就是「结论是否与判据一致」「有效条数你填了 9，应为 17」这种句子。

**判据（改这层代码时必须守住）**：同一份日志转出来的提交，
`trace_audit.call_count` 要等于日志行数（不含产物行），`schema_valid` 要是 `true`；
`tests/test_lab.py::test_logged_trial_ends_in_a_real_report` 盯的就是这条。
