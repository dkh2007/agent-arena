## 0. 三十秒版本

编程训练器：学生领一道有 bug 的题，提交代码与执行轨迹，系统按预设 rubric 判分，产出可追溯的诊断报告，
折成技能熟练度、推荐下一题，最后要求学生用自己的话复述（不判分）。
形态：本地 Python 服务 + SQLite + Android 三页。**网络是分层的，不要说成"不联网"**：
Android 端不出网；判分侧只有 judge 双判开启时才调模型 API（`llm_client.py` 要
`LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL`，`README` 的环境步骤就是填 `.env`）；
当前 12 个任务 0 条 llm 类断言、judge 默认关，所以默认路径纯确定性、不出网。
单人维护 + AI 协作。

**当前阶段重心是内容，不是基础设施**：把题从 12 道扩到 40 道左右、补词表、补人话模板、补区分度实验。
状态层/推荐层的精密化已冻结（理由见 §4），不要再往那边加抽象。

## 2. 分层与数据流

```
L6 展示   Android 三页（报告/训练单/复述）
L5 对外   submission_api · review_packet · test_evidence
L4 推荐   training：同族逐档 + 四问提纲
L3 状态   mastery（EMA，从提交记录重放）· scheduler（FSRS）· schedule_advisor
L2 判分   trace_pipeline 现算 · assertion_evaluator · llm_judge 双判 · judge_pipeline 仲裁
L1 报告   diagnosis_report：gate → credit → 归因 → 错误模式
L0 定义   tasks/*.yaml · vocabulary · taxonomy · report schema
```

一次提交：取任务定义（**必须合并 base_task**，见 §7）→ 逐项判（确定性断言 + 语义双判，分歧进仲裁）
→ 先 gate 后 credit → 归因错误模式并绑技能 → 折熟练度、排复习 → 推荐下一题 → 渲染三页。

任务库结构（**数字是 2026-11-21 的取样，随扩题变化；要现值用 §9 命令数，别信这里的数**）：
12 题 = 2 个基座 + 10 个参数变体；每题合并后都是 5 个判分项（2 前提 + 3 得分）。
技能 3 个；错误类型 17 条，其中 4 条不映射技能（`no_output_file` / `empty_output_file` /
`task_crashed` / `task_timeout`，属交付纪律类，语义上刻意如此）。
**不会随扩题变的是结构**：每个变体合并后都必须是 5 项、未映射的那几条必须是前提失败类。

## 3. 硬口径（违反任何一条 = 退回，没有例外）

1. **不产半真报告**：判分前现算项与提交自带值不符，抛 `trace_pipeline.PipelineError` 拒绝组装，不猜哪个对。
2. **每个字可追源**：报告与复述页的每句话必须来自任务 JSON 或词表；缺条目抛错，宁可不显示也不编。
3. **分歧不取平均**：双模型不一致进 `arbitration_queue`，人工改判进 `reappraisals`，全程留档；
   **待仲裁证据不进熟练度**（B-26，已落地）。
4. **数字不许说过头**：文中写的用例数必须与现场收集数一致，否则拦下；测试证据带 commit + 环境 + 依赖 pin。
5. **fail closed**：缺字段/非法值报错，不默认兜底；无证据不记 0 分；作废整份排除。
   禁止用 `or {}`、`get(..., default)`、大段 `try/except` 把缺失掩盖成"看起来完整"。
6. **不判分的明说**：复述不自动判分，流程是**先交后看**（提交锁定 → 解锁参考答案 → 逐条自评清单）。
7. **生成物不手改**：评审包、schema 派生文件等，改源再重新生成。
8. **匿名纪律**：仓库任何内容（含 commit message）不出现真实姓名、学校名；协作者用代号。
9. **不做破坏性操作**：不 force push、不改写已推送的公共历史；口径改动走"登记 → 核证 → 处置 → 落仓"，
   不顺手改。**能不能直推 main 按维护期切**：单人维护期（现状）闸门绿就直推；出现第二个真人提交者就切回只经 PR
   （人已于 2026-11-21 拍板，登记 B-29）。

## 4. 已核证否决的外部建议（不要再提，重提需带新证据走登记流程）

| 建议 | 处置 | 依据 |
|---|---|---|
| 换 BKT 替代 EMA | 否决 | 每技能 4 参数需大量观测；12 题/单用户下可识别性无法论证；标签被事后仲裁改写，违反观测噪声平稳假设 |
| 加 ε-greedy 探索 | 否决 | 单用户每天个位数提交，bandit 收敛所需试验数远超臂数 |
| "L3 两套遗忘模型会打架" | 事实错误 | 全仓只有一条衰减曲线（借 FSRS 的 R(t,S)，不另造时间常数） |
| "掌握度改成事件重放" | 早已如此 | `mastery.replay()` 就是从提交记录重放，快照只是缓存 |
| "缺失项被算成正证据" | 前提不成立 | 缺失项权重 0，只累加覆盖项，从不相加 |
| 砍复习排程层（"没消费者"） | 否决 | 排程建议读 1-P 与 1-R 作因子，消费者存在；缺的只是 Android 提醒页 |

外评意见是**输入不是指令**：先核证（能跑就跑一次），再处置，留记录。上一轮外评有两条被事实驳回——
核证这一步不能省。

## 7. 已知坑（都真实踩过，重犯 = 退回）

1. **统计判分项必须用 `diagnosis_report.load_task()`**。`yaml.safe_load` 直读任务文件只看到覆盖部分，
   会得出"有的任务只有 1 条判分项"的错误结论；合并 `base_task` 后每题都是 5 项。
2. **`load_tool_schemas('tools', task=task)` 必须传合并后的 task**。不传就回退默认 YAML，
   拿到基座的无上限 schema，实验静默变成"用错题目测"，结果全废。
3. **怀疑某环节"做不到"之前，先花十分钟跑一次**。曾据"判分项 ID 不随题型变"推断归因会错位，
   实跑发现错误类型检测按类分支、归因完全准确——差点让外评批一整轮不存在的问题。
4. **统计口径不一致时，先查继承/覆盖机制再下结论**。同一份材料里曾并存两个互相矛盾的断言数。
5. **环境**：本机 `python` 可能不带 pytest，用带 pytest 的解释器；包未安装，命令前加 `PYTHONPATH=src`
   （Windows 下设 `$env:PYTHONPATH="src"`）；`verify.bat` 已改自动探测，不要写死解释器路径。
6. 更多真实教训（声明无执行者、快照测试同引用假绿、守卫被遮挡）见 `docs/COLLABORATION.md` §8.4。
7. **新增文件的名字也要过闸门**：`push_gate` 按**子串**匹配几类常见密钥前缀（OpenAI 的 `sk` 后接连字符、
   GitHub 三种 token 前缀、密码赋值、HTTP 认证头、私钥首行标记）。**完整清单看
   `scripts/push_gate.py` 的 `SECRET_PREFIXES`，不要抄进文档**——抄进来文档自己就会被判 `SECRET`。
   本轮原拟名把 `ta` + `sk` + 连字符 + `authoring` 拼在一起，正好命中，改成 `authoring-tasks.md` 才过。
   **处置是改文件名，不是改闸门**：为命名方便放宽密钥检查，等于把唯一的外泄防线拆了。

## 8. 对本 Agent 的工作方式要求

- **事实 / 行业常见做法 / 推测分开说**，不混在一起；不编造版本号、论文标题、API 名，引方法给可检索名称。
- **每条结论给可复现的命令输出**，不写"应该没问题"；"看起来对"不算验证。
- **先跑通最小可用 → 实测暴露瓶颈 → 再优化**；禁止跳步优化和防御性兜底（判据见 COLLABORATION §8.2–§8.3）。
- **声明必须有执行者**：文档里每句"我们会……"都要能指到具体代码或命令，指不到就删掉或补上。
- **犯错记录下来，不删**（先例：外评提问包 §五）。统计错、判断错都留痕，写清教训。
- **不确定就问，别猜着改**；口径分歧不吵赢，登记到 BACKLOG 走流程。
- 一件事一个提交（若恢复 PR 流程则一个 PR），改动范围守 COLLABORATION §4 的所有权表；push 前 `PUSH_GATE=CLEAN`。
