## 一、项目概述

**一句话定位**：Agent 开发学习领域的**自适应诊断与训练闭环**——学习者提交 Agent，系统对其执行轨迹做错误诊断（不只打分），把错误模式映射到技能缺口，按遗忘规律调度**可执行的任务变体**作为复习项，并按"掌握度 + 遗忘风险 + 错误热度 + 项目截止"生成训练日程。

**参赛赛题（2026-11-20 明确绑定）**：第二十届全国大学生软件创新大赛 **赛题 1「AI 赋能学习生产力——面向移动终端的场景创新」**。
契合点逐条对应赛题原文：①赛题要求学生"处理课件、录音、文档、图像、手写等多种内容"并"在不同应用、设备和场景之间持续开展学习"→ 本作品把分散的练习记录收敛成技能级诊断；②赛题鼓励"发挥移动设备随身使用、现场采集、触控手写、即时交互及多设备协同的特点"→ 本作品的移动端是学习闭环主入口（随时看诊断、领训练单、做限时练习、收复习提醒），电脑端只承担 Agent 开发与提交；③赛题要求"让记录服务于理解，让知识积累支持实践与创造"→ 本作品不输出分数榜单，输出"错在哪个技能、下次练什么"。

**解决的问题**：Agent 开发课程供给已充足（Microsoft/OpenAI/Hugging Face 均有系统课程），但练习环节断裂：作业一次性、无持续评测；主流 Agent 评测基准面向评模型、出榜单，不服务学习者。学习者改完一版 Prompt 后，没有任何工具回答：**这次错在哪个技能上？和上次是同一类错吗？接下来该练什么、什么时候练？**

**核心方案（五层闭环）**：
1. **任务层**：细分域任务库（MVP 聚焦工具调用与多步任务调试），每任务标注技能节点 + 可注入的错误模式
2. **评测层**：自动断言（文件/API 调用/状态变化/最终输出）+ LLM-as-Judge（计划合理性、内容质量）+ **轨迹分析**（中间步骤、工具调用序列、重试行为）→ 输出**错误诊断报告**而非分数
3. **状态层**：错误模式 → 技能缺口映射；技能节点级掌握度模型（**自研 EMA + 时间衰减**，见 §4.2-8；**不取 FSRS 的 D/S/R**）
4. **复习层**：复习项不是卡片，是**可执行任务**——同技能新变体、注入故障的调试题、限时练习、错题重放（复现上次失败轨迹要求修复），由 FSRS 调度
5. **排程层**：掌握度、遗忘风险、错误热度、项目截止四因子共同驱动，输出**建议排期**（用户保留控制权）

**交付形态（2026-11-20 定稿）**：**Android 原生应用**（Kotlin + Jetpack Compose），承载诊断报告 / 训练单 / 费曼复述 / 复习提醒，是学习闭环的主入口；Web 端只承担 Agent 开发与提交。Streamlit 仅作内部开发工作台，**不进入交付物**。

**当前进度快照（2026-11-21，可现场核验）**：本计划书描述完整蓝图，其中**评测层、状态层、推荐口径与移动端三页已实现并跑通**——单元测试 **1583 个用例全绿**（`pytest tests/ -q`，1583 passed / 0 failed；每次运行的档案留存在 `docs/test-evidence/INDEX.md`，含 commit、环境、逐文件用例数）；任务库 12 个已建；首个任务 `dbg-001-order-report` 用五份不同质量的假提交跑出 **0 / 0.25 / 0 / 0 / 1.00** 的区分度（明细见 §4.6）；掌握度（自研 EMA + 时间衰减）与复习排程已编码，可跑出成绩单（`scripts/mastery_scorecard.py`；掌握度 + 排程 + 调度共 140 条测试通过）；规则推荐已落地为「同族逐档」（§4.2-6，`src/arena/training.py` + 30 条测试）；费曼复述页已落地为「三问提纲 + 三种输入 + 数据来源提示层」（`src/arena/feynman.py` + 24 条测试）；Android 原生**报告页、训练单页与费曼复述页**已在模拟器上跑通并实拍（`docs/images/android-report-final.png`、`android-training.png`、`feynman-text.png`）。**尚未完成**：复习提醒页、掌握度回测——逐项见 §六。
**阅读约定**：§4.6 之内是**已实测**，§4.6 之外（除特别标注）是**设计陈述**。两者不混写。

## 二、背景与问题分析

### 2.1 需求真实性（2026-11 检索核实）

- 课程供给爆发：Microsoft《AI Agents for Beginners》（18 课开源）、OpenAI Building Agents、Hugging Face Agents Course（3 万+ star，结业需过 GAIA 子集自动评测）。
- HF 课程反证缺口：GAIA 子集 20 题 + REST 评分 API + 排行榜 = 一次性结业考；精确匹配打分，无轨迹诊断、无掌握度、无复习调度。
- 评测侧成熟实践（可借鉴机制）：PinchBench（Kilo Code 出品，147 个任务；任务 = Markdown + YAML frontmatter，评分项写成**原子可验证清单**，三种评分方式：自动脚本 / LLM 裁判 / 两者加权混合）、ClawBench V2（130 任务 / 63 真实站点；环境是真实网站 + 浏览器扩展而非沙箱；**会话记录分五层并可在网页里回放**）、千问 AI Arena（2026-08-12 上线；从真实业务产生挑战任务，"**机器打榜 + 专家盲审**"两级筛选）。**它们评模型出榜单；评"人"且驱动学习的，没有。**

### 2.2 学习科学依据（机制 ↔ 研究，可核验）

| 机制 | 依据 |
|---|---|
| FSRS 调度可执行任务 | 记忆模型源自 Ye, Su & Cao, KDD 2022（doi:10.1145/3534678.3539081，提出 SSP-MMC / DSR 三值模型）；FSRS 是开源社区据此衍生的调度器，Python 实现为 py-fsrs（MIT）。Anki 自 23.10 起**首次内置支持**，官方手册将其定位为 SM-2 的 alternative、需在牌组选项中手动启用；**23.10 是「首次支持」的版本，不是「成为默认调度器」的版本**（后续版本对新安装的默认状态另有调整，此处不作断言）；迁移到可执行任务的创新在技术层创新点论证。**本表只把 FSRS 用于「何时再练」；掌握度不取它的任何数值**（见 §4.2 第 8 条）——这一句是限定，不是补充说明 |
| 重练优于重看（测试效应） | Karpicke & Roediger, Science 2008, 319:966-968（doi:10.1126/science.1152408）：40 组外语词对，一周后持续提取组约 80%、停止提取组约 33–36%。**实验材料是陈述性记忆，迁移到可执行编程任务属机制启发与设计类推，不是直接实证**；故本项定位为「机制启发」，不宣称已由该实验验证 |
| 费曼复述 + AI 反馈 | Dunlosky et al., Psychological Science in the Public Interest 2013, 14(1):4-58（doi:10.1177/1529100612453266）：self-explanation 与 elaborative interrogation 均评为 **moderate（中等效用）**，high 档只有 practice testing 与 distributed practice。故此处定位为「辅助机制」，不作为高效证据 |
| 错误驱动推荐 | **设计动机**：推荐需可解释（为什么推这道）；错误模式 → 技能缺口为规则链，可逐步回溯。原写法「KT 领域公认开放问题」未取得可核验来源，已撤回该定性，此处只陈述本系统做法 |
| 元认知校准 | IES/NCER 项目 R305H050038（Dunlosky 团队, Kent State, 2005–2008）提出的 retrieval-feedback-monitoring（RFM；后续项目亦作 Retrieval-Monitoring-Feedback / RMF）方法：提取 → 反馈 → 自我判断 → 据此排程。**这是具体研究方法名，不是通用「范式」**；本项只取其「监测准确性影响排程」这一机制 |

### 2.3 目标用户与场景

上完 Agent 入门课、想动手但不知道练什么/错在哪的开发者与在校学生（团队本人即用户，dogfooding）。核心场景：PC 开发提交 → 手机收诊断报告（挂了哪些原子断言、错误模式归类、修复建议）→ 按训练单做变体任务/错题重放/费曼复述 → 间隔到期推送下一轮。

### 4.1 架构（五层）

```

│ 技能图谱：技能节点（如"工具参数校验""失败重试策略"）  │
│ 错误模式标签（参数幻觉/循环不收敛/未检查返回值…）      │

├─ 评测层（管线自研，底座调开源，见 4.5）──────────────┤

├─ 状态层（FSRS 开源底座 + 自研增量）─────────────────┤
│ 技能节点掌握度（自研 EMA）；错误模式热度统计            │
│ 错误模式 → 技能缺口映射表（自研核心）                 │
├─ 复习层（自研，调度调 py-fsrs）───────────────────┤
│ 复习项=可执行任务：新变体/故障注入调试题/限时练习/     │
│ 错题重放（复现失败轨迹要求修复）；FSRS 调度到期时间    │
├─ 排程层（自研）──────────────────────────────────┤
│ 四因子建议排期：掌握度+遗忘风险+错误热度+项目截止      │

└──────────────────────────────────────────────────┘

云：Python FastAPI + PostgreSQL + 任务队列；LLM 走云端 API（JSON 结构化输出）
```

### 4.2 关键技术决策（均有已核实先例或明确对策）

> **编号约定（v0.5 新增）**：本节条目引用为 **§4.2-1 … §4.2-11**。对外决策包（`review-snapshot/review-packet.md` §3）
> 用的是另一套编号 **D1–D11**，两套**不是同一个序列**——例如 §4.2-11 是「两处缺东西处置相反」，D11 是
> 「任务版本不一致 ⇒ 作废」；§4.2-1 是「黑盒提交」，D1 是「首发域」。只有 8 / 9 / 10 三条因搬运而恰好同义。
> 因此引用时**一律带前缀**，不写裸的「决策 8」。

1. **黑盒调用式提交**（HF 课程模式）：学习者将 Agent 部署为公开可调用服务，平台只调用 + 评分 + 收集 trace，不做不可信代码沙箱——砍掉最大工程量。**代价**：黑盒测不出的能力（如错误恢复细节）依赖 trace 上报，故规定**最小 trace schema** 为提交格式的一部分（不报轨迹的任务仅得断言分+judge 分，无诊断报告——用产品机制倒逼上报）。
2. **错误分类学的冷启动**：分类学不从零发明——从公开 Agent 评测的失败模式（"命名不一致/目录缺失/日期陷阱"类工程挑战已有先例）+ 团队 dogfooding 的真实 trace 归纳起步，随数据迭代。v1 规模由 **M2 的错误分类学交付**定（里程碑表已写 5–8 个模式 + 技能映射表）；判据是每条模式至少有两个真实 trace 实例且有判定层执行者，达不到就不进 v1，先留在候选表里——不先填一个没有数据支撑的数。
   - 〔2026-11-20 口径校准〕首个任务 `dbg-001` 的三个积分断言**合计声明 10 条错误模式**（3+3+4）。此处的"5–8"指
     **跨任务去重后的技能节点级模式数**，不是单任务标签数——两个计数口径必须写清楚，否则 10 > 8 会被读成超限。
     去重结果以 `tasks/*.yaml` 里 `error_pattern` 的 id 集合为准：**当前 17 种**——12 个任务共引用 17 个 `pattern_id`，
     与 `docs/error-patterns-v0.yaml` 词表逐一对应（无"词表有、任务不用"的孤儿项）；
     **若去重后确实 >8，改本节数字，不反过来删 YAML**。
3. **变体任务模板化**：任务 = 情景变量（领域/数据/故障注入位）+ 固定 rubric 骨架，一个模板生成 N 个变体，摊薄任务库成本；FSRS 调度的是变体实例。
4. **Judge 一致性**：双评 + 不一致率阈值 + 人工仲裁；人工样本留档算一致率。阈值由 **M1 的 `scripts/judge_agreement_experiment.py` 实测**定：同一提交重复评 N 次打一致率分布，取"人工仲裁成本 ≤ 误判代价"处的最小仲裁比例；分布出来之前不写阈值（脚本刻意不设默认值，理由见其模块文档）。
5. **复习负担控制**：可执行任务成本高于卡片，每日复习队列设上限（示例值 2 项不是承诺），宁可拉长间隔不堆量。上限由 **M4 的 dogfooding** 定：记录连续两周的"当日队列完成率"，取完成率不低于 80% 的最大项数；达不到 80% 就下调并拉长间隔，不靠硬堆。
6. **推荐先规则后模型，且规则按「同族逐档」而非「按技能筛」**（2026-11-20 定，依据见下行）。
   MVP 用规则推荐，不上深度知识追踪（冷启动数据近零，复杂模型跑不出可信结果）；预留 **pyBKT**（伯克利开源 BKT 库，可解释）作升级接口。
   - **为什么改口径**：12 个任务里 `secondary_skill_ids` 有 11 个贴同一组标签（多步任务分解 12/12、工具参数校验 11/12、失败重试策略 11/12），按技能筛不出「该做哪道」，推哪个都差不多。
   - **改成了什么**：读任务已有的 `variant_meta.family_id / difficulty`，推**同一族的下一档**（四个族各 2–3 档）；「练什么」逐字取下一档任务的 `scenario`，「怎么算练会」是固定判据（门禁全过 + 积分全过），「回来核对哪条」取当前报告的失败断言。
   - **没做什么**：不跳档、不做「薄弱点加权」（没有真实数据定权重，硬定等于编）；族尾不编造更难的任务。实现 `src/arena/training.py`，30 条契约测试，含「改 YAML 里难度后推荐必须跟着变」的变异用例。
7. **评分分两段（gate → credit），分界判据是"可补偿性"而不是"重要性"**：
   - gate 只收**前提性条件**（当前是「交了产物」「进程正常退出」）：它们失败时，"这个任务完成了吗"本身没有答案，不属于能力维度；credit 收**能力维度**（结果正确 2 / 重试证据 1 / 无参数幻觉 1），按权重加权、允许互相补偿。
   - 一条条件能进 gate，需同时满足三条：**① 不可补偿**——它失败时，其余分数不能被解释成"部分完成"；**② 有明确后果**——失败即整份 0 分，且门禁不计权重（配置层有执行者强制校验，违反直接报错，不是注释约定）；**③ 不吞诊断**——门禁失败时 credit 层照常判定，另存"若算分能得几分"，只是不计入总分。
   - 文献对应：Wheeler (1993) 的 combined model（"在两个及以上决策层级上作决定"）；conjunctive 与 compensatory 之分见 National Academies (2011) ch.5。
   - **假阳性/假阴性的权衡有直接实测**：Yocarini et al. (2018, *EMIP* 37(3):24-39, doi:10.1111/emip.12186) 用真实数据驱动的模拟得出——conjunctive 规则**假阴性更高、假阳性更低**，compensatory 反之；哪条规则更准取决于平均信度、测验间相关与补考次数。本项目取的就是这个取舍方向：宁可让"没交产物"判 0（假阴性），也不让它拿分（假阳性）。
   - **文献里多重门槛的主要理由是成本，这条对本项目不成立**：Ock & Oswald (2018, *Journal of Personnel Psychology* 17(4):172-182) 的模拟显示，补偿式在多数条件下期望效标表现与总体效用**更高**；多重门槛仍被采用的理由，是昂贵环节只施加于通过前置筛选的人、可省施测成本。本项目断言在算分前已全部跑完，不省任何成本（见下条诚实边界），**故不引用该理由**。若有人以"补偿式更准"反驳，本条不辩——我们换的不是准确率，是失败模式的取舍。
   - 一条诚实边界：文献中"顺序筛除降低评估成本"这条理由在本项目**不成立**——断言在算分前已全部跑完，不因门禁失败而跳过。故不作为依据。
   - 反证条件：若某条条件失败时仍能给出有意义的 credit 解释（即它可以被部分补偿），它就不该在 gate 层，应移入 credit 并赋权。
8. **掌握度与调度分开记，且只用一个时间轴**：掌握度 = 最近做题表现的指数平滑并随时间衰减（衰减只沿用"复习间隔"这一个时间轴，不另立第二套衰减公式）；"什么时候再练"由间隔重复卡片的参数决定。**不把卡片的 stability 当掌握度的衰减系数**——它的定义是"可提取性降到 90% 所需天数"，与平滑系数不同量纲，二者只能经一个**待标定的映射**关联（登记为假设，须留出数据做消融验证）。
   - 文献支撑的边界（三句话，各自管一段）：**「掌握判据用简单 EMA 就够」有直接文献**——Pelánek & Řihák (2018) 系统比较多种掌握判据后，结论是数据源与阈值的选择比模型技术更重要，简单指数滑动平均适合做判据；**「时间衰减取什么函数形式」有文献基线**——Pelánek (2014, EDM) 比较了指数/幂/对数衰减与 Elo 在学生建模中的表现；但**「只拿复习间隔当唯一时间轴」是本项目的设计选择，不是文献结论**，须留出数据消融验证。
9. **缺过程按题目类型分流**：任务自己声明"要不要过程"。要过程的题缺过程 ⇒ **本次不计能力分、不计掌握度、不产错误模式**，记一条中性流程事实并提示补交；只交答案的题照常算分。**缺过程是流程事实，不是能力判断**；写"没思路"也算交了过程，不把"没写"当"不会"。
10. **答案必须可对账**：答案里的数值要能在提交的过程记录里找到出处；**对账不通过 ≠ 答错**，落"未验证"（不计掌握度、不记短板）。前提是过程记录里含被用到的数值——这是补记录字段的理由，不是放弃对账的理由。随机化测试输入只作补充，不替代对账（它挡的是"抄上次答案"，挡不住"过程是真的、结论是编的"）。
11. **两处「缺东西」的处置相反，禁止合成一句话**（2026-11-14 外部评审指出的合并陷阱）：
   - **过程有缺口**（要求过程的题没交过程）＝ 流程不完整 ⇒ 本次不计能力分、不计掌握度、不产错误模式，只记一条中性流程事实（口径见第 9 条）。
   - **过程完整但结果没交**（trace 齐全、可验证的习惯都在，只是产物缺失）＝ **完成分记 0**（任务确实没完成），但过程里可验证的习惯——不瞎猜参数、失败会重试——**照记进技能档案**。两条轴分开显示、不混算：分数列写 `0（本次不合格，任务未完成）`，技能列写 `重试规范 ✓（本次证据来自不合格提交）`。
   - **为什么不能合成一句**：前者是"没按规矩交过程"，后者是"交了完整过程、只是没交成果"，判据与后果正好相反。合并会让评委以为系统在惩罚"过程不完整"，与实际口径不符；也会让学习者分不清"我该练流程还是练交付"。
   - **已知代价（不藏）**：这条口径下，"只交过程、不交产物"的提交能拿到过程类技能的证据，权重与一次正常通过相同。当前成绩只给学习者自己看（不进综测/评优/对外排名），故不构成可利用的漏洞；**一旦开排名，必须先把这类证据的计入口径从"全额"改成"降权"，再上榜单**，否则"交白卷但重试规范"能把名次刷上去。

### 4.4 评测指标

1. **"没交产物"与"交了但没过程"被分成两种不同的零**——`raw-no-file` 是门禁未过，`raw-no-trace` 是门禁通过、

3. 每行 `pass + fail + blocked + unscored` **恒等于 5**（断言总数），可逐行自查。

**四、judge 双评一致性（2026-11-14 实测）**

- 三批实验、**8 组双评中 7 组两次评档完全一致**（87.5%）；唯一分歧样本是 `raw-no-trace`
  ——它在 5 次评价里的档位为 `[3,2,3,3,3]`，只往低档掉过一次，且耗时（12–20 秒）显著高于其他样本（1.7–5.4 秒）：
  "答案对、过程全空"这个形态会让裁判反复权衡。
- 全部为本机真调用 `deepseek-flash`，未做任何修饰；原始记录 `docs/judge-agreement-distribution.json`。
- **只报数、不报阈值**：按 §4.4，一致率的用途是估算人工仲裁成本，8 组的样本量不足以支撑一条阈值线，
  写一个阈值会比不写更容易误导。

## 五、创新点（三条可证伪陈述）

1. **问题/场景层**：Agent 评测现有格局是"评模型出榜单"或"一次性结业考"，无面向学习者的持续诊断系统；本项目以执行轨迹错误诊断为核心服务"课程学完之后"的学习者。——证伪：官网获奖名单与主流平台检索查重。
2. **技术层**：将间隔重复模型从静态卡片迁移到**可执行任务变体**（含故障注入与错题重放），并把错误模式→技能缺口映射作为推荐依据，给出 AUC 与修复成功率等可复现指标。——证伪：M3/M4 回测数据可复核。
3. **状态/交互层**：掌握度、遗忘风险、错误热度、项目截止四因子联合排程 + 用户保留控制权，区别于手动日历与全自动排程两个极端；费曼复述与情景录入共享同一能力状态。——证伪：dogfooding 采纳率数据。
> **初赛（盲审只有计划书）时点，三条各自的可判性分开写**（v0.5 修正原句"三条均绑定纸面可判的外部证据"）：
> 第 1 条靠**检索查重**判（定稿前动作，§三已列）；第 2、3 条的**指标定义与回测 / 统计脚本已实现**，
> 可在纸面上给出命令与定义并核对，但**数据本身在复赛阶段才产出**（M3 回测、M4 dogfooding）。
> 不把尚未产生的数据写成"已可核验"——这是本项目对自身主张的一贯口径，本句也不例外。
