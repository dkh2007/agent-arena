## 5. 收工清单（每次改完必跑，按顺序）

```
1. pytest tests/ -q                    → 全绿（数字记下来）
2. python src/arena/review_packet.py --check        → 0
3. python src/arena/review_packet.py --check --full → OK_FULL（**必须在工作区静止时跑**）
4. python scripts/push_gate.py --self-test --dirty c830b1b → SELF_TEST_PASS=True
5. python scripts/demo_decision.py --all            → FAIL 必须为 0
6. 若改了测试 → 必须重生成评审包（`_pytest_count()` 会变 ⇒ 必 STALE）
   **且要生成两次**：第一次会把"包内旧数字 ≠ 现在数字"记成 `1 failed`（RC=2），
   第二次才收敛到 RC=0（自指互锁，见 C-03）
7. 本文件与 ROADMAP 的状态行跟着改
```

**纪律提醒**（都是踩过的坑）：
- `--check OK` **不**证明源码实现仍在（禁用一段实现照样绿，§47.4）。要证明用针对性测试 + 变异。
- `--full` 若报一堆红，先确认是不是"一边改文件一边跑"造成的假红。
- 加测试 ⇒ `_pytest_count()` +1 ⇒ 评审包必 STALE ⇒ 要么重生成，要么这一步不并入批次。
- 判据的期望值**必须先跑再写**（§61.7 / §63.7 两次凭印象预填都写错了）。
