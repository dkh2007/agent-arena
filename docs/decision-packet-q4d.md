## 1. 为什么提前到 A 线

外评 round-57 指出：`docs/review-packet.md` §3 决策 7 是「**数据缺失 ≠ 能力不足**：
`blocked` / `unscored` 一律不计入掌握度、不产出错误模式」，而 Q4(d) 问的正是「没调目标工具
要不要升级成可训练失败信号」——即给决策 7 开例外。这与 P1（掌握度定义）、
P2（全 `unscored` 时怎么更新）是同一层判断，须同批拍板，否则会出现
「计划书先写死『数据缺失不计能力』、之后 Q4(d) 又开例外」的自相矛盾。

**A 线的交付物是决策包，不是代码。** 本包只负责把判断题与判据摆清楚，结论由人给。

## 3. 判断题（只一条）

**「学习者完全没调目标工具」应当怎么归因？**

| 选项 | 内容 | 代价 |
|---|---|---|
| **(a)** | 维持 `unscored`：数据缺失，不计掌握度、不产出错误模式 | 零改动；但「故意跳过工具直接写答案」也落这个洞 |
| **(b)** | 升级为**可训练失败信号**：产出独立错误模式、计入掌握度 | 须扩 DTO 枚举（TD-008 惯例）+ 词表 + 测试 + 改决策 7 |
| **(c)** | 维持 `unscored`，另记一条**不计入掌握度**的观测注记，供复习层提示 | 须定义字段落点；若注记进了 `error_patterns` 则实质等于 (b) |

## 4. 判据（什么算通过，不是「我觉得」）

1. **可分性**：选 (b) 前必须回答「这个信号能否区分『不会用工具』与『故意跳过工具硬编码答案』」。
   不能区分就与评审包 §5 P3 的防作弊初衷冲突——后者正是要用 R6 产物/轨迹一致性堵这个洞。
2. **落点**：选 (c) 必须写清注记落在哪个字段、是否进 `error_patterns`；进则按 (b) 处理。
3. **不变量**：任何选项都不得改变五夹具分数 `0 / 0 / 0.25 / 0.5 / 1.0`（硬锁）。
4. **决策 7**：选 (b) 或 (c) 且进入掌握度时，必须同步修订评审包 §3 决策 7 的适用条件，
   否则「纸面写死、实现开例外」会变成新的文档失真。
5. **验证**：结论须配一个十分钟内能跑的本地裁判（见 §6），不接受「这样应该没问题」。

## 5. 我方倾向（**假设**，附反证条件，不替人拍板）

倾向 **(a) 维持现状**，但只作为待核证的起点：决策 7 的初衷是防止「数据缺失被记成能力不足」，
而「没调工具」目前无法从 trace 单独区分原因。

- **反证条件**：若 M0「一好一坏两个 Agent 跑分」的对照里，「坏 Agent 完全不调目标工具」是
  **可复现**的能力差异信号（而非提交侧偶然行为），则 (a) 的教学价值不足，应改 (b) 或 (c)。
- **第二反证条件**：若评审包 §5 P3 的 R6 一致性校验落地后，已能把「不调工具却报对数」判为异常，
  则 (b) 的独立信号是重复建设，反而应维持 (a)。
- 这两条都属**产品意向 + 运行事实**，AI 不代决。
