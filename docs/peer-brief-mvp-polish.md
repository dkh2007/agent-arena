# 给后期润色者的 MVP 精简清单

> 一份简短说明：目前是一个人搭工程骨架，另一位做后期润色。目的是**别把力气花在现在不该做的东西上**。
> 本文件只提方向与取舍，不改任何判定口径；口径以 `docs/BACKLOG.md` 与计划书为准。

## 钦定的改进方向（只此一个）

**把"分数怎么来的、凭什么可信"讲清楚，而不是再加功能。**

骨架里已经有一批能跑的东西（断言现算、两段式 gate/credit、证据留痕、对账、平台采集、
行集重放）。作品现在缺的不是新模块，是**让评委在十分钟内看懂这条链**的呈现：
一份报告能顺着读出「工具返回了什么 → 哪条断言据此判过 → 分数为什么是这个数」。
润色优先落在这条叙事线上——术语统一、前后一致、把每一步的证据指向标清。
**任何增加新评分规则、新判据的建议都先不要动**，那要改口径、要重跑全部验证。

## 现在不必要（做了反而有害）

| 项 | 为什么现在不做 |
|---|---|
| 排行榜 / 班级榜 | 掌握度口径还没切防刷模式，白卷能排第一；且"比较能提升意愿"未验证。开工条件见 B-25 |
| 标定任何阈值（一致率 / 难度系数 / 排程权重 / AUC 固定值） | 没有真实学习者数据，标出来是拟合噪声，还会被评委当承诺。等 M3；AUC 已定"没有基线分布就不写死数字" |
| 真实复习事件 / 标记"已复习" | 要等移动端界面才有这个动作；现在建表就是有表无行为（B-08c） |
| 多目标任务的覆盖率谓词 | 目前只有一个单目标任务，需求没出现（B-24） |
| 重新解释 T2 那批提交 | T2 既没分也没正向证据，说了只制造焦虑；T3 才需要在界面上说，且措辞是"证据按当时判据记录"，不是"成绩错了" |
| 伪造/润色 trace 让报告更好看 | 报告是判定结果，改它等于改证据；要让结果好看只能改真实行为 |

## 一条边界

报告的 `notes` 字段学生会看到。任何写进去的话都只陈述**中性事实 + 下一步**，
不出现"编造/作弊/不合格"这类定性词。判定细节放结构化字段给评审看，不放给人话区。

## 要动手之前

先跑一次仓库里的验证入口（一键脚本），确认是绿的再改。改完重跑一次。
不确定某件事该不该做，就对照 `docs/ROADMAP.md` 的"还没做"一栏——**列在里面且带前置条件的，就是还没轮到**。
