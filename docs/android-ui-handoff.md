## 3. 组件规格

- **SurfaceCard** — 白底 + `1dp Line` 描边 + 18dp 圆角 + 16dp 内边距，无阴影。
- **ScoreRing** — 直径 116dp、描边 12dp、Round 端点、从 -90°（12 点）顺时针；
  底槽 `Track`，前景按 `ratioTone()`。中心 27sp Bold 分数 + 10sp「得分率」。
- **StateChip** — 胶囊，内边距 10×5，11sp；计数为 0 时前景 `Ink3`、底 `LineSoft`。
- **LossBar** — 高 6dp 全圆角，`Track` 打底，`Fail` 填充，最小可见比例 5%
  （避免 1/20 这种小值在屏幕上消失）。
- **DiffLine** — 字段名 62dp 宽 `12sp Ink3`；`期望`标签 12sp + 值 12.5sp Medium `Ink2`；
  `实际`标签 12sp + 值 12.5sp SemiBold `Fail`。
- **StatusDot** — 8dp 圆，颜色取 `stateTone()`。
- **WeightChip** — 胶囊 10.5sp，底 `LineSoft`，字 `Ink2`；`weight == 0` 时显示「门槛项」。

## 4. 页面信息顺序（不要随意调换）

身份 → 总分（环 + 三项数字 + 状态胶囊）→ 技能缺口（按权重损失降序）→
断言明细（gate 在前，credit 在后，与 JSON 同序）→ 过程材料 → 判定说明（有则显示）→
**下一步**（有训练单才出现）→ 数据来源。

顺序本身就是论述：先给结论，再给理由，最后给证据来源。判定说明排在过程材料之后，
因为它是「这个结论对你意味着什么」，不是新证据。**「下一步」是页尾唯一的行动号召**：它读 `training-plan.json` 的族与下一档，
不是页面自己想的建议；没有训练单时整块不出现，不写「敬请期待」。
**页尾是「样例来源」，不是联网状态**——
2026-11-20 之前这里有一张「联调（演示时可跳过）／探活后端」卡片，点一下会打印
`127.0.0.1:8080`，评委翻到最后一屏只会看到开发者信息，且它占掉了「下一步该练什么」的位置。
探活改为在电脑侧用 `adb reverse` + `curl` 完成（见 `android-build.md` §6.6）。

## 4.5 训练单口径（B：同场景逐档）

「下一档练什么」不按技能推，按**同一个族、难度 +1** 推。原因有据可查：12 个任务里
`secondary_skill_ids` 有 11 个贴同一组标签（多步任务分解 12/12、工具参数校验 11/12、
失败重试策略 11/12），按技能筛不出差别；而 `variant_meta.family_id / difficulty` 本来就有，
四个族各 2–3 档。

| 项 | 值 / 来源 |
|---|---|
| 族与档位 | 任务 YAML 的 `variant_meta.family_id` / `variant_meta.difficulty` |
| 「练什么」的文字 | 下一档任务的 `title` + `scenario` 里的编号条目（逐字，不改写） |
| 「怎么算练会」 | 固定规则：下一档上门禁全过、积分全过（得分率 1.00、未判不合格）。**是规则不是阈值** |
| 「回来看哪条」 | 当前报告 `skill_gaps[].failed_assertions` 的并集 |
| 生成命令 | `python -m arena.training --task tasks/<任务>.yaml --from-report android/app/src/main/assets/sample-report.json --out android/app/src/main/assets/training-plan.json` |

三条不许自作主张的地方：① 只走一档，不跳档、不做「薄弱点加权」（没有数据定权重）；
② 同族同档多题时取 `task_id` 最小者，是为了确定性，不是「更推荐」；
③ 族尾不编造更难的任务。

## 4.6 费曼复述页口径

费曼复述的价值在「不看材料先讲一遍，再拿材料对照」。所以这一页的结构是固定的：
**三问提纲 → 输入 → 缺口 → 对照 → 来源**，四步都不能挪到前面去。

| 项 | 值 / 来源 |
|---|---|
| 三个复述问题 | `feynman.py` 的 `QUESTIONS` 常量（固定文案，属产品口径，不是数据推断） |
| 「这次没过的」 | 报告 `skill_gaps`：中文技能名取词表 `name`，错法标签取词表 `label` |
| 「讲完对照」 | 每条失败断言的 `evidence.extra.diffs`（期望 / 实际）+ `note` / `why`，逐字 |
| 「提示」里的四条 | 要求清单（任务 `scenario`）、期望与实际、错法解释（词表 `description`）、现场（`note`/`why`） |
| 输入方式 | 文字 / 语音 / 手写：文字走键盘；语音调系统识别器把结果接进文本框；手写只存笔迹 PNG |
| 草稿 | `SharedPreferences("feynman-draft")`，键名带 `task_id`（换题即另一份草稿） |
| 生成命令 | `python -m arena.feynman --from-report android/app/src/main/assets/sample-report.json --task tasks/dbg-001-order-report.yaml --out android/app/src/main/assets/feynman-prompt.json` |

**为什么不给复述打分**：没有第二个真值来源。接 LLM 判分要额外成本、还要防幻觉，
在没有对比实验之前，任何「你讲得 80 分」都是编的。这一页只做两件事——
把该讲的摊开、把你的原话存住（含「复制全文」，方便拿出去让别人评）。

**手写为什么不识别成文字**：端上离线识别要引模型（体积、许可都是新风险），在线识别违反
「这一页不发网络请求」。所以定位是草稿纸，页面必须写明「不会自动转成文字」——
不写这句，用户写完发现没变字会当成 bug。

**输入方式为什么用胶囊 + 下拉，而不是底部 Tab**：切换的是「怎么打字」，不是「去哪一页」。
底部 Tab 会让人以为换了功能；胶囊紧贴输入区，切完还在原地。

## 4.7 键盘与系统栏（踩过的坑，别改回去）

- `MainActivity` 里 `WindowCompat.setDecorFitsSystemWindows(window, false)` + Scaffold
  `contentWindowInsets = systemBars ∪ ime`。**实测结果**：状态栏避让有效（内容从状态栏下方开始）；
  **键盘避让在本机模拟器上没有生效**（ime inset 恒为 0，页面不缩小）。
- 因此复述页把「草稿已存 / 复制全文」放在输入框**上方**，不依赖 inset 是否分派正确。
  这一行是「我写的东西存住没」和「我要把这段话拿出去」，恰恰是键盘打开时最想看到的。
  改回输入框下方 = 键盘一弹就被压住（2026-11-20 的原始版本就是这样）。

## 5. 红线（违反即为 bug，不是审美分歧）

1. **界面里不许出现硬编码的业务数值。** 所有数字来自 `assets/sample-report.json`
   （或后端返回），页面只做格式化，不做计算。
2. **不许改判据口径。** 得分率 = `weighted_sum / total_weight`，分母固定为权重合计，
   不因失败项减少而变小。这是产品主张，不是显示细节。
3. **门槛项（`weight == 0`）不进分母**，显示文案是「门槛项」，不写「权重 0」。
4. **中文展示名只许来自报告的 `display_labels`。** 它是评测管线从
   `docs/skill-taxonomy-v0.yaml` 的 `name` 与 `docs/error-patterns-v0.yaml` 的 `label`
   读出来、随报告下发的。页面里**不许**再写 `when (id) { "multi_step_planning" -> "多步规划" }`
   这类映射表——2026-11-20 就存在过这样一张表，与词表三条全不一致（页面写「合计金额算错」，
   词表里是「总额算错」）。旧报告缺这个字段时回退原始 id，那只是兼容路径，不是常态；
   未知字段名同理回退，不许猜一个中文名。
5. **`disqualified` / `voided` 必须显式显示**，不许为了版面干净藏起来。
6. **不许加入场动画让首帧与真实值不一致。** 2026-11-20 踩过：环形进度做 720ms 补间，
   模拟器不在前台时帧不推进，截图里环是空的，看起来像 0 分。现在直接按真实值绘制
   （`ReportScreen.kt` 的 `ScoreRing` 注释里写了原因）。
7. **换肤只改 `Theme.kt`。** 页面里的形状/颜色必须引用常量，不许新写字面量。
8. **`notes` 必须原样显示，不许改写、不许挑着显示。** 这些句子是判定的一部分：
   「本次不计能力分、不计入掌握度，**不视为能力不足**」——少这一句，学生只看到 0 分，
   会当成「我被判死刑」。空数组时整块不出现，不许留空卡、不许写「暂无」。
9. **训练单与报告必须对账，`task_id` 不一致就报错、不显示建议。** 两份 JSON 是分别生成的，
   错位的训练单会让人练错题——比没有训练单更糟。这条在 `TrainingScreen.kt` 里有对应分支，
   删掉它等于把「两个文件恰好同步」当成不变量。
10. **族尾（`top_of_family`）与无族（`no_family`）必须明说，不许编一档。** 「再难一点」听起来
   很积极，但那一档并不存在时，学生练完发现没有下一步，比一开始就说「到顶了」更伤。
11. **页面里不许出现调试入口、本机地址、`adb` 命令。** 这些是开发手段，不是产品功能。
    想看后端通不通，在电脑侧 `adb reverse tcp:8080 tcp:8080` 后 `curl` 即可；
    界面上一旦出现 `127.0.0.1`，评委看到的就是「没做完」。新增调试入口请用
    独立的 debug 专用 Activity，不进主页面。
12. **不许给复述打分、不许给鼓励语。** 「不错，继续加油」「这次讲得比上次清楚」都是编的：
    没有第二真值源，也没有纵向数据。页面上只能出现材料、你自己的原话、以及「由你自己对照」。
13. **手写不许假装识别。** 画板只存笔迹；「不会自动转成文字」这句必须留着。
    去掉它，用户写完没看到文字会认为功能坏了——这比没有手写更伤。
14. **语音不可用必须明说。** `isRecognitionAvailable` 为 false 时给解释，不给按了没反应的麦克风。
15. **提示里的每一行都必须来自数据包。** 不许在 `HintRow` 里临时拼一句「你可以想想分页边界」——
    那既不是评测结论，也无法追到任务定义。要加提示，先让 `feynman.py` 产出它。

## 6. 加一页的最小步骤

1. 在 `ReportScreen.kt` 同目录新建 `XxxScreen.kt`，容器用 `Components.kt` 里已有的
   `SurfaceCard / BackRow / NoticeCard / Tag`，别复制一份改颜色。
2. 布局只用 `CardShape / PillShape / ListGap / CardPad / T*` 这些常量。
3. 页面要显示的数据先让 Python 侧产出一份 JSON（参照 `arena/training.py`、`arena/feynman.py`），
   页面只解析、不推断；再写一份 `XxxModel.kt` 做解析与 `task_id` 对账。
4. `MainActivity.kt` 的三页状态机里加一个分支与入口（仍不引导航组件）。
5. 编译 + 截图 + 按第 7 节对账；截图存 `docs/images/`，文件名以页面开头（如 `feynman-*.png`）。

## 8. 换技术栈时怎么搬

所有 token 都是纯数值，与 Compose 无关：颜色是十六进制，字号 ≈ dp/sp，
圆角与间距是 dp。搬到 Flutter / React Native / Web 时：

- 建一份 `tokens.{dart,ts,css}`，把第 2 节原样抄过去；
- 环形进度换成任意 canvas 的 `arc`，参数照抄（直径 116、线宽 12、起点 -90°、Round 端点）；
- 「期望 / 实际」对比块是纯排版，不需要图表库。
