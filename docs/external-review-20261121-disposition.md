## 二、两条要当场纠正的（回件错了，或我写错了）

1. **不存在"两套遗忘模型打架"。** 全仓只有一条遗忘曲线：py-fsrs 的 `R(t,S)`。
   掌握度的 `P` 是能力估计，衰减时乘上 `R`（`decay.decay_p`），排程层明确不衰减 P。
   → 回件这条不采纳；同时我订正 `architecture-for-review.md` 里"λ 和半衰期两个参数"的说法：
   **半衰期不是我们的参数**，我们只有一个自由参数 λ（默认 0.3）。

2. **"缺失被当成正证据"不成立。** 缺证据的断言进 `ignored`、权重 0，从不相加。
   回件把"整份不合格仍照记"读成了"缺失算正"，这是两件事：前者是口径选择（已覆盖项算不算数），
   后者是实现事实（从不相加）。→ 口径问题交人拍，实现不改。

## 三、本轮实际做的（可复核）

外部建议里唯一"便宜且能当场判定"的一条是：**先做参数敏感性分析，再谈校准**。
已落成 `scripts/param_sensitivity.py`：λ 网格 × 衰减时刻网格，看**技能排序是否翻转**
（排序顺序才是下游 `mastery_gap` 因子真正吃的东西，结论比"P 变了多少"更贴近决策）。

```bash
python scripts/param_sensitivity.py                 # 内置 4 份演示提交
python scripts/param_sensitivity.py --db path.db --user someone
```

脚本内置一条自检：λ=1.0 时 P 必须等于最后一条计入证据的 c（数学上必然），不等就报错退出——
防止脚本本身算错却输出"看起来很稳"的表。

实测（内置 4 份演示提交 / 3 个技能，2026-11-21）：

```
自检通过：λ=1.0 时 P 等于最后一条计入证据的 c。

| 技能                    | λ=0.1 | λ=0.3 | λ=0.5 | λ=0.7 | λ=0.9 | λ=1.0 |
| failure_retry          | 0.910 | 0.790 | 0.750 | 0.790 | 0.910 | 1.000 |
| multi_step_planning    | 0.900 | 0.700 | 0.500 | 0.300 | 0.100 | 0.000 |
| tool_param_validation  | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 |

基准排序（λ=0.3）：tool_param_validation > failure_retry > multi_step_planning
λ 网格内相对次序反转：0 对（每个 λ 都是 0）

衰减维（距各自最后一条证据 N 天，括号内是 FSRS 的 R）：
  +  1 天：0.777(R=0.98) · 0.536(R=0.77) · 0.983(R=0.98) → 反转 0 对
  +  7 天：0.720(R=0.91) · 0.408(R=0.58) · 0.911(R=0.91) → 反转 0 对
  + 30 天：0.626(R=0.79) · 0.327(R=0.47) · 0.792(R=0.79) → 反转 0 对
  + 90 天：0.541(R=0.68) · 0.276(R=0.39) · 0.685(R=0.68) → 反转 0 对
```

怎么读这张表（避免把它读成"参数没问题"）：

- **能说的**：在本库这 3 个技能上，λ 从 0.1 扫到 1.0、衰减从 1 天推到 90 天，技能排序一次没翻。
  排序是 `mastery_gap` 因子真正吃的东西，所以"参数影响决策"在这组数据上没有出现。
- **不能说的**：3 个技能、4 份提交，P 之间的间距很大（0.98 vs 0.78），排序当然稳。
  **真实用户数据上必须重跑**；技能数到十几个、P 值靠得很近时才是真考验。
- **顺带观察**：`failure_retry` 的 P 随 λ 是 U 形（0.910→0.750→1.000），因为它最后两条证据一好一坏；
  `multi_step_planning` 随 λ 单调降（0.900→0.000）。同一个 λ 在两个技能上作用方向相反，
  说明"λ 调大就更有最近偏好"这种直觉不成立——λ 的效果取决于证据序列本身。
